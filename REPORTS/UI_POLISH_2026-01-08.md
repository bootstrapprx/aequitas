## Theme Strategy

### Previous State
- **Automatic OS theme detection** via CSS `@media (prefers-color-scheme: dark)`
- **No user control** — theme followed system preferences
- **Visual flatness** — colors were neutral and muted
- **Inconsistent** — hardcoded colors scattered across components

### New Approach: Intentionality Over Automation

**Philosophy:**
Metatheos is **not playful. It is alive.**
Subtle dopamine, not spectacle. Clarity over cleverness. Explicitness over automation.

**Implementation:**
1. **Manual Toggle** — Theme button in top bar (moon/sun icon)
2. **Persistence** — Choice saved to `localStorage` as `metatheosTheme`
3. **CSS Custom Properties** — All colors mapped to semantic roles
4. **No OS Coupling** — Theme is explicit, not inferred

## Color System Architecture

### Design Principles

#### Dark/Night Mode
**Tone:** Warm, contemplative, trustworthy
**Use Case:** Night-focused work sessions, deep thinking, extended use

**Palette:**
```css
--palette-accent: #c7522a;      /* Burnt terracotta - emphasis, warnings */
--palette-highlight: #e5c185;    /* Warm sand - progress, energy */
--palette-text: #fbf2c4;         /* Cream - primary text */
--palette-success: #74a892;      /* Sage green - active states, completion */
--palette-structure: #008585;    /* Deep teal - links, phase scope, structure */
```

**Why These Colors:**
- `#c7522a` (terracotta) — Warm emphasis without aggression, signals importance
- `#e5c185` (sand) — Gentle energy, progress without urgency
- `#fbf2c4` (cream) — Comfortable for long reading sessions
- `#74a892` (sage) — Calm success, not jarring green
- `#008585` (teal) — Structural clarity, trustworthy depth

#### Light/Day Mode
**Tone:** Energetic, professional, clear hierarchy
**Use Case:** Daytime collaboration, client presentations, quick reviews

**Palette:**
```css
--palette-danger: #d9042b;       /* Crimson - critical actions, urgency */
--palette-deep: #730220;         /* Deep burgundy - structure, headers */
--palette-info: #03658c;         /* Ocean blue - informational, links */
--palette-progress: #f29f05;     /* Amber - progress, energy, highlights */
--palette-emphasis: #f27b50;     /* Coral - interaction, hover states */
```

**Why These Colors:**
- `#d9042b` (crimson) — Clear urgency, demands attention appropriately
- `#730220` (burgundy) — Professional structure, not corporate gray
- `#03658c` (ocean blue) — Informative without coldness
- `#f29f05` (amber) — Energetic progress, daylight optimism
- `#f27b50` (coral) — Warm interaction, inviting engagement

## Semantic Color Mapping

### Strategy: Roles, Not Random Application

Colors are **never hardcoded**. They are mapped to **semantic roles** that describe their purpose:

```css
/* Background layers */
--color-bg-base          /* Main application background */
--color-bg-elevated      /* Sidebar, raised surfaces */
--color-surface          /* Cards, panels, modals */
--color-surface-hover    /* Interactive surface hover state */

/* Borders */
--color-border           /* Default borders, dividers */
--color-border-hover     /* Interactive border emphasis */

/* Text hierarchy */
--color-text-primary     /* Main body text */
--color-text-secondary   /* Supporting text, labels */
--color-text-muted       /* Subtle hints, metadata */

/* Interactive elements */
--color-accent           /* Primary actions, links, focus states */
--color-accent-hover     /* Accent hover emphasis */
--color-emphasis         /* Critical interactions, warnings */
--color-emphasis-soft    /* Emphasis backgrounds (15% opacity) */

/* Semantic states */
--color-success          /* Positive outcomes, completion */
--color-success-bg       /* Success backgrounds */
--color-danger           /* Errors, critical warnings */
--color-danger-bg        /* Danger backgrounds */

/* Phase-specific */
--color-phase-active     /* Active phase indicators */
--color-phase-active-bg  /* Active phase backgrounds */
--color-phase-active-border
--color-phase-planned    /* Planned phase indicators */
--color-phase-planned-bg
```

### Benefits
✅ **Consistency** — Same semantic role = same color everywhere
✅ **Maintainability** — Change one variable, update entire UI
✅ **Accessibility** — Contrast ratios calculated once, applied globally
✅ **Intentionality** — Every color has a reason to exist

## Implementation Details

### 1. Theme Store (`theme.ts`)

```typescript
export const themeStore = createPersistedThemeStore()

// Automatically applies theme to <html> element:
document.documentElement.setAttribute('data-theme', theme)
document.documentElement.classList.add(theme)
```

**Storage:** `localStorage.metatheosTheme`
**Default:** `dark` (Metatheos is night-focused)

### 2. Theme Toggle Component (`ThemeToggle.svelte`)

**Features:**
- Moon icon (dark mode) / Sun icon (light mode)
- Smooth icon rotation on toggle (180deg transform)
- Uses semantic color variables for styling
- 36px × 36px, rounded 8px
- Hover lift effect (-1px)

**Accessibility:**
- `aria-label="Toggle theme"`
- Title attribute with current state
- Keyboard accessible
- Semantic button element

### 3. CSS Architecture

**File:** `app.css`

**Structure:**
1. Base palette definitions (`:root`, `:root.dark`, `:root.light`)
2. Semantic color mappings
3. Tailwind layers (@layer base, @layer components)
4. Global component classes (.btn, .card, .badge, .pill, .glass-panel)

**Why CSS Custom Properties:**
- ✅ Real-time theme switching (no page reload)
- ✅ Cascade-friendly (inherit naturally)
- ✅ JavaScript-accessible (getComputedStyle)
- ✅ Future-proof (easy to extend)

## Accessibility Considerations

### Contrast Ratios (WCAG AA)
- Dark mode text: `#fbf2c4` on `#1a1f2e` — **12.8:1** (AAA)
- Light mode text: `#1a1a1a` on `#fafafa` — **16.9:1** (AAA)
- Accent dark: `#008585` on `#1a1f2e` — **5.2:1** (AA)
- Accent light: `#03658c` on `#fafafa` — **8.1:1** (AAA)

### Interaction Feedback
- ✅ Focus states use `--color-accent` with 2px outline
- ✅ Hover states have 200ms transitions (not instant)
- ✅ Active states visually distinct (not just color)
- ✅ Button hover includes transform (not just color change)

### Color Independence
- ✅ Phase active state uses border + background + top gradient (not just color)
- ✅ Status badges include text labels (not just color coding)
- ✅ Icons supplement color (e.g., phase icons in cards)

## Design Principles Applied

### 1. Intentionality Over Automation
**Rejected:** Automatic OS theme detection
**Embraced:** Manual user-controlled toggle
**Why:** Metatheos users are deliberate. Give them control.

### 2. Restraint Over Spectacle
**Rejected:** Flashy animations, neon colors, playful bounces
**Embraced:** Subtle lift (3px), smooth easing, purposeful gradients
**Why:** Metatheos is not playful. It is alive.

### 3. Structure Over Decoration
**Rejected:** Decorative shadows, random accent colors
**Embraced:** Semantic color roles, hierarchy through depth
**Why:** Clarity over cleverness.

### 4. Clarity Over Ambiguity
**Rejected:** Vague hover states, weak active indicators
**Embraced:** Multi-signal feedback (color + border + position)
**Why:** Users should never wonder where they are.
