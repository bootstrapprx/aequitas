### Issue 2: ingest_roadmap Command Failed ❌

**Problem:** Terminal error when running `ingest_roadmap`:
```
Found NONE for field `created_at`, with record `phase:P0`, but expected a datetime
```

**Root Cause:** Using `.update().content()` on non-existent records doesn't trigger schema defaults

The issue was:
```rust
// OLD (broken)
let _: Option<serde_json::Value> = db
    .update(("phase", seed.code))
    .content(phase_payload)  // Full replace on non-existent record = no defaults
    .await?;
```

When using `.update().content()` on a record that doesn't exist yet, SurrealDB:
1. Creates the record (since update acts like upsert)
2. BUT doesn't apply schema defaults because it's an UPDATE operation
3. Field `created_at` ends up as NONE instead of `time::now()`

**Fix:** Use proper create-or-merge pattern

```rust
// NEW (correct)
let existing: Option<serde_json::Value> = db
    .select(("phase", seed.code))
    .await?;

if existing.is_some() {
    // Record exists - use MERGE (only updates specified fields)
    let phase_updates = json!({
        "title": seed.title,
        "description": description,
        "status": seed.status,
        "order_index": seed.order_index,
    });
    let _: Option<serde_json::Value> = db
        .update(("phase", seed.code))
        .merge(phase_updates)  // Preserves existing created_at
        .await?;
} else {
    // Record doesn't exist - use CREATE (applies defaults)
    let phase_payload = json!({
        "id": seed.code,
        "title": seed.title,
        "description": description,
        "status": seed.status,
        "order_index": seed.order_index,
        // created_at omitted - schema default will apply
    });
    let _: Option<serde_json::Value> = db
        .create(("phase", seed.code))
        .content(phase_payload)  // CREATE applies schema defaults
        .await?;
}
```

**Why this matters:**
- `CREATE` = Applies all schema defaults
- `UPDATE + MERGE` = Preserves existing fields, only updates specified
- `UPDATE + CONTENT` = Full replacement, no defaults (dangerous)

**Files Modified:**
- [commands.rs:3978-4066](metatheos/metatheos-gui/src-tauri/src/commands.rs#L3978-L4066)
- Fixed for both `phase` and `goal` records

**Impact:** `ingest_roadmap` now works correctly, preserves timestamps on re-run

## Design Patterns Learned

### Pattern 1: Modal Exit Routes

**Always provide multiple exit paths:**
1. ✕ Close button in modal header
2. Backdrop click (outside modal)
3. ESC key (bonus)
4. Cancel button in modal footer

**Implementation:**
```svelte
<div class="backdrop" on:click={close}>
  <div class="modal" on:click|stopPropagation>
    <button class="close" on:click={close}>✕</button>
    <form>
      ...
      <button type="button" on:click={close}>Cancel</button>
    </form>
  </div>
</div>
```

### Pattern 2: SurrealDB Upsert Semantics

**Rule:** Different operations have different default behaviors

| Operation | On Existing Record | On Non-Existent Record | Schema Defaults |
|-----------|-------------------|----------------------|-----------------|
| `CREATE` | Error (conflict) | Creates record | ✅ Applied |
| `UPDATE + MERGE` | Updates specified fields | Creates with specified fields | ❌ Not applied |
| `UPDATE + CONTENT` | Replaces entire record | Creates with content | ❌ Not applied |
| `SELECT then branch` | Explicit control | Explicit control | ✅ When using CREATE |

**Best Practice for Upsert:**
```rust
// 1. Check existence
let existing = db.select(("table", id)).await?;

// 2. Branch logic
if existing.is_some() {
    // Update only changed fields
    db.update(("table", id)).merge(updates).await?;
} else {
    // Create with defaults
    db.create(("table", id)).content(payload).await?;
}
```

### Pattern 3: UI Component Placement

**Notification badges belong in:**
1. ✅ Top-right of main app header (standard)
2. ✅ Fixed position top-right corner (overlay)
3. ❌ Sidebar header (cramped)
4. ❌ Mixed with logo/branding (confusing)
