You are Claude Code working inside the Aequitas repository.
Your task is to fully implement the "Users Management" module, which is currently only a placeholder.

This module must respect the new identity hierarchy:
- Users always belong to one or more Companies.
- Normal users cannot create other users.
- Superusers can create, edit, assign companies, remove company assignments, and deactivate users globally.
- Company admins can ONLY create/edit users inside their own company.
- Users cannot exist without a company association, except the global superuser (actpm@aequitas.com).

## HIGH-LEVEL OBJECTIVES
Implement a complete Users Management page that supports:

1. Listing users:
   - If logged-in user is superuser:
     → list ALL users in the system.
   - If logged-in user is company admin:
     → list ONLY users inside their company(ies).

2. Viewing user details:
   - Basic info: email, UID, status, roles, last login
   - List of companies the user belongs to

3. Creating users:
   - Superuser: can create any user and assign to ANY company.
   - Company admin: can ONLY create users inside their own company.
   - Enforce no user creation without company assignment.
   - User must receive a generated UID (backend already implemented or must be added if missing).
   - Generate temporary password or allow admin to set initial password.

4. Editing users:
   - Change email, roles (admin inside a company), active/inactive status.
   - Add/remove companies the user belongs to (respecting permission scope).

5. Deleting / Deactivating users:
   - Hard delete only allowed for superuser.
   - Company admins may only deactivate users inside their company.

6. Security:
   - Enforce strict backend permission checks.
   - Validate that updates do not orphan a user (remove all companies → forbidden unless superuser and target is superuser).

7. Frontend UI:
   - Table with search, filters, pagination.
   - Drawer / modal for Create User.
   - Drawer / modal for Edit User.
   - Select component to choose which companies the new user belongs to.
   - Status indicators (active, suspended, admin).
   - Company badges in table rows.

## BACKEND REQUIREMENTS (FastAPI)

### 1. Routes
Create new router at:
`backend/app/api/v1/users_management.py`

Endpoints:

GET /admin/users  
- Only for superusers  
- Returns all users with:
  - id, email, user_uid, is_superuser, created_at, last_login, companies[], is_active, roles

GET /companies/{company_id}/users  
- For company admins & superusers  
- Returns users belonging to that company

POST /users  
- Create user  
- Payload:
  {
    "email": "...",
    "password": "...",             # optional, if empty generate random temp password
    "company_ids": [...],          # required unless creating superuser
    "roles": {"is_admin": true|false},
    "is_active": true
  }
- Enforce:
  * superuser can assign ANY company
  * company admin can assign ONLY their companies
  * user must have at least one company unless superuser

PUT /users/{user_id}  
- Update email, companies, roles, is_active  
- Enforce same rules as create

DELETE /users/{user_id}  
- Soft delete (set is_active=False) for company admin  
- Hard delete allowed only for superuser

GET /users/{user_id}  
- Fetch details + companies + roles

### 2. Validation Rules
