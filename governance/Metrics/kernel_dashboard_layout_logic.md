# Dashboard Layout Logic

This pass answers **one question only**:

> *How does a human experience all of this without being overwhelmed, misled, or rushed into bad decisions?*

No accounting rules are redefined here.
No Canon language is added.
This is **experience logic**, not UI polish.

---
**Role:** Experiential layer
**Goal:** Reveal truth progressively, never prematurely
**Audience:** Founder, accountant, auditor, investor (same screen, different depths)

---

## 1. The Prime Rule of Layout

> The dashboard does not ask the user to think.
> It asks the user to *notice*.

Everything is organized around **attention flow**, not feature availability.

---

## 2. Dashboard Entry Point (First Screen)

### What the user sees immediately

Exactly **five elements**, no more:

1. **Total Cash**
2. **Net Revenue (current period)**
3. **Operating Income**
4. **Net Working Capital**
5. **Current Ratio**

Nothing else is visible.

No charts below.
No side panels.
No tabs.
No projections.

### Why

This answers, in under 5 seconds:

> “Is this company alive, generating value, and liquid?”

If the user closes the app here, they still got value.

---

## 3. Core Metrics Layout (Tier 1)

### Structure

* One row
* Five cards
* Equal visual weight

### Behavior

* Each card shows:

  * current value
  * delta vs prior period
  * simple arrow (up / down)

No colors beyond:

* neutral
* subdued warning (only if extreme)

No explanations unless the user taps.

---

## 4. Unlocking Tier 2 (Advanced Metrics)

### Unlock Condition

Tier 2 becomes visible only if **all Core Metrics are displayed without critical distress**.

This is not “healthy”.
This is “stable enough to explain”.

### User Action Required

A deliberate action:

* “Show operational details”
* or scrolling past the Core section

Nothing auto-expands.

---

## 5. Tier 2 Layout (Operational Understanding)

### Grouping (Very Important)

Tier 2 is split into **three blocks**, always in this order:

---

### Block A — Profit Structure

* Gross Margin
* Operating Margin

**Question answered:**

> “Are we making money the right way?”

---

### Block B — Cost Structure

* Payroll Ratio
* Operating Expense Ratio

**Question answered:**

> “What is consuming the money?”

---

### Block C — Cash Timing

* DSO
* DPO
* Cash Conversion Cycle

**Question answered:**

> “When does money actually move?”

---

### Visual Rules

* Each block fits on one screen height.
* No mixing across blocks.
* Each metric shows:

  * value
  * trend
  * tap-for-breakdown

---

## 6. Tier 3 Access (Diagnostics)

### Default State

Tier 3 is **hidden**.

Not collapsed.
Hidden.

### How it becomes visible

One of the following must occur:

* User explicitly opens “Diagnostics”
* User taps “Why?” on a Tier 2 anomaly
* User enters Audit / Review mode

---

## 7. Tier 3 Layout (Truth & Risk)

### Tone Shift

When Tier 3 is opened, the dashboard **changes tone**:

* Slower animations
* More text
* Fewer colors
* Explicit disclaimers

This signals:

> “You are now interpreting accounting reality.”

---

### Tier 3 Grouping

#### Group 1 — Profit vs Cash

* Operating Cash Flow (estimated)
* Earnings Quality Ratio

**Narrative:**

> “Is profit supported by cash?”

---

#### Group 2 — Revenue Integrity

* Refund Rate
* DSO trend overlay

**Narrative:**

> “Is revenue reliable?”

---

#### Group 3 — Fiscal Pressure

* Tax Coverage Ratio
* Tax Drift Indicator

**Narrative:**

> “Is tax stress accumulating quietly?”

---

#### Group 4 — Capital Sustainability

* Depreciation Intensity
* Asset Intensity Ratio

**Narrative:**

> “Is the asset base decaying or scaling?”

---

### Mandatory Rule

Every Tier 3 metric must display:

* components used
* what changed
* what that usually means
* what it does **not** mean

No exceptions.

---

## 8. Simulation Layer (Separate Space)

### Absolute Rule

Simulations **never appear on the main dashboard**.

They live in:

* a separate tab
* or a dedicated “Scenarios” mode

---

### Entry Requirement

User must:

* acknowledge assumptions
* select drivers manually
* confirm “this is hypothetical”

---

### Simulation Presentation

* Side-by-side comparison:

  * Actuals (locked)
  * Scenario (clearly marked)

No blending.
No overlays.
No confusion.

---

## 9. Navigation Philosophy

### The dashboard is vertical, not modular

You scroll **down into depth**, not sideways into features.

This reinforces:

> Surface → Structure → Truth → Hypothesis

---

## 10. Anti-Patterns (Explicitly Forbidden)

* ❌ Default projections on landing
* ❌ Red/green scorecards
* ❌ “Recommendations”
* ❌ Alerts without explanation
* ❌ One-click “fixes”
* ❌ Ranking companies
* ❌ Gamification

Any of these breaks the Canon.

---

## 11. Final Experience Principle

The user should leave each session with **one of three feelings**:

1. “I’m safe.”
2. “I understand what’s happening.”
3. “I know what questions to ask next.”

If the dashboard causes:

* panic,
* false confidence,
* or dependency,

it has failed.
