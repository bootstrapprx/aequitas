### 2. Staging Database Model (`backend/app/db/models/staging_qbo_account.py`)

**Purpose:**
- Stores RAW QuickBooks account data as received from Go worker
- Append-only table (NO updates, NO deletions)
- Acts as isolation boundary between external data and authoritative accounting tables

**Schema:**

```python
class StagingQBOAccount:
    id: UUID                      # Primary key

    # Tracing & Correlation
    job_id: UUID                  # Go worker job ID
    request_id: UUID              # X-Aequitas-Request-Id
    correlation_id: UUID          # X-Aequitas-Correlation-Id

    # Company Reference (NOT FK - isolation boundary)
    company_id: UUID              # Target company

    # Source Data (Raw from QuickBooks)
    source: str                   # Always "quickbooks"
    source_account_id: str        # QuickBooks account ID
    name: str                     # Account name
    account_type: str             # QuickBooks type (raw)
    account_subtype: str          # QuickBooks subtype (raw)
    active: bool                  # Active status
    currency: str                 # Currency code

    # Raw Payload
    raw_payload: JSONB            # Complete account object from Go

    # Metadata
    imported_at: datetime         # When staged
    created_at: datetime          # Created timestamp
```

**Indexes:**
- `ix_staging_qbo_accounts_company_job` - Composite index on (company_id, job_id)
- `ix_staging_qbo_accounts_source_id` - Index on source_account_id
- `ix_staging_qbo_accounts_imported_at` - Index on imported_at

**Critical Rules:**
- ✅ Append-only design
- ✅ NO foreign key to companies table (isolation)
- ✅ NO accounting validation
- ✅ NO mapping or classification
- ✅ Complete raw_payload preserved

### 4. Service Layer (`backend/app/services/integration_job_service.py`)

**Class:** `IntegrationJobService`

**Responsibilities:**
- Trigger jobs in Go worker
- Receive and process callbacks
- Stage raw data
- Enforce idempotency

**Key Methods:**

#### `async trigger_job()`

```python
async def trigger_job(
    job_trigger: JobTriggerRequest,
    request_id: str,
    correlation_id: str,
    idempotency_key: Optional[str] = None,
) -> JobTriggerResponse
```

**Flow:**
1. Validate request
2. Build canonical headers (`X-Aequitas-Request-Id`, `X-Aequitas-Correlation-Id`, `X-Aequitas-Idempotency-Key`)
3. POST to Go worker `/jobs` endpoint
4. Return job_id from Go worker

**Error Handling:**
- `AEQ_WORKER_UNREACHABLE` - Cannot connect to Go worker
- `AEQ_WORKER_REJECTED` - Go worker rejected request

#### `process_callback()`

```python
def process_callback(
    callback: JobCallbackPayload,
    request_id: str,
    correlation_id: str,
    idempotency_key: Optional[str] = None,
) -> JobCallbackResponse
```

**Flow:**
1. Check idempotency (if key provided)
2. Route by job_type
3. Stage raw data
4. Store idempotency record
5. Return success response

**Job Type Routing:**
- `qbo.sync_accounts` → `_process_qbo_sync_accounts()`

#### `_process_qbo_sync_accounts()`

**CRITICAL DESIGN:**
- NO accounting validation
- NO mapping or classification
- NO ledger operations
- ONLY raw data staging

**Flow:**
1. Extract accounts from callback result
2. For each account:
   - Parse as `QBOAccountRaw`
   - Create `StagingQBOAccount` record
   - Store raw_payload exactly as received
3. Commit to database
4. Return count of staged records

**Idempotency:**
- Checks `idempotency_keys` table
- Returns cached response if key already processed
- Stores response after successful processing

### 5. API Endpoints (`backend/app/api/v1/integration_jobs.py`)

**Router:** `/api/v1/integrations`

#### Endpoint 1: Trigger Job (Python → Go)

```
POST /api/v1/integrations/jobs
```

**Authentication:** Required (JWT)
**Authorization:** User must have permission for company
**Status Code:** 202 Accepted

**Headers:**
- `X-Aequitas-Idempotency-Key` (optional)

**Request Body:**
```json
{
  "job_type": "qbo.sync_accounts",
  "company_id": "uuid",
  "payload": {
    "realm_id": "1234567890",
    "access_token": "bearer-token",
    "full_sync": false
  },
  "callback": {
    "url": "http://localhost:8000/api/v1/integrations/jobs/callback",
    "auth": "internal"
  }
}
```

**Response:**
```json
{
  "job_id": "uuid",
  "status": "accepted"
}
```

**Observability:**
- Logs job trigger with request_id, correlation_id, user_id, company_id, job_type
- Propagates canonical headers to Go worker
- Logs success/failure with job_id

#### Endpoint 2: Receive Callback (Go → Python)

```
POST /api/v1/integrations/jobs/callback
```

**Authentication:** Internal (no JWT required)
**Authorization:** Should be protected by network policy in production
**Status Code:** 200 OK

**Headers:**
- `X-Aequitas-Request-Id` (required from Go)
- `X-Aequitas-Correlation-Id` (required from Go)
- `X-Aequitas-Idempotency-Key` (optional from Go)

**Request Body:**
```json
{
  "job_id": "uuid",
  "job_type": "qbo.sync_accounts",
  "company_id": "uuid",
  "status": "succeeded",
  "result": {
    "accounts": [
      {
        "id": "1",
        "name": "Cash",
        "type": "Bank",
        "subtype": "CashOnHand",
        "active": true,
        "currency": "USD",
        "source": "quickbooks"
      }
    ],
    "source": "quickbooks",
    "count": 245
  },
  "errors": []
}
```

**Response:**
```json
{
  "status": "accepted",
  "message": "Staged 245 accounts",
  "records_staged": 245
}
```

**Observability:**
- Logs callback receipt with request_id, correlation_id, job_id, job_type, status
- Warns if canonical headers missing (but doesn't fail)
- Logs staged record count

## 🧠 Key Design Decisions

### 1. Staging Table Has NO Foreign Key to Companies
**Decision:** company_id is UUID but NOT a foreign key.
**Rationale:** Isolation boundary. Staging table should not depend on authoritative tables.
**Trade-off:** Cannot use CASCADE DELETE, but acceptable for staging layer.

### 2. Append-Only Staging Design
**Decision:** NO updates or deletes on staging_qbo_accounts.
**Rationale:** Preserves complete audit trail. Duplicates handled via idempotency at endpoint level.
**Trade-off:** Table grows over time, but staging data can be archived.

### 3. Idempotency Enforced in Python (Not Go)
**Decision:** Go is "idempotency-aware" but Python is authoritative.
**Rationale:** Python owns data persistence. Go just logs/propagates keys.
**Trade-off:** Slightly more complex Python logic, but correct authority boundary.

### 4. Callback Endpoint NOT Authenticated via JWT
**Decision:** Go → Python callback uses internal trust, not JWT.
**Rationale:** Service-to-service internal call. Should be protected by network policy.
**Trade-off:** Requires secure network in production (VPC, API gateway, etc.).

### 5. Raw Payload Stored in JSONB
**Decision:** Store complete account object as-is from Go.
**Rationale:** Preserves all data for debugging. Future-proof if QBO adds fields.
**Trade-off:** Slight storage overhead, but negligible for account data.
